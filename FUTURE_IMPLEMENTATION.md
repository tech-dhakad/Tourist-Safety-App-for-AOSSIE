# 🔮 Future Implementation & Decentralization 

Raahi follows a phased hybrid-decentralization strategy. While the current system balances
performance and decentralization, the following improvements are planned to further reduce
central dependencies and increase user sovereignty.

## Phase 1: Data & Storage Decentralization
- Expand IPFS usage for all safety reports, route logs, and incident metadata
- Introduce cryptographic content verification using CIDs
- Enable multi-node IPFS pinning for redundancy

## Phase 2: Backend Federation
- Migrate Flask backend to a multi-node federated architecture
- Stateless API instances with shared decentralized storage
- Explore serverless and edge-based execution

## Phase 3: Decentralized Identity (DID)
- Integrate DID-based user identities
- Eliminate centralized user accounts
- Enable privacy-preserving authentication

## Phase 4: On-chain Verification (Optional)
- Blockchain-based verification for critical safety reports
- Transparent and auditable incident history without financialization

## Phase 5: DAO-based Governance
- Community-driven moderation of safety data
- Proposal-based feature upgrades
- Open voting for protocol changes

## Phase 6: Fully Modular AI Layer
- Support for multiple LLM providers
- User-owned API keys by default
- Offline and rule-based AI fallbacks
